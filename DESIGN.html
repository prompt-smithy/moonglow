1. Requirements

Functional (macOS parity)

  • External-monitor brightness over DDC/CI (1–100%).
  • Scheduled colour temperature: day/night targets with morning/evening transition windows, plus a manual mode.
  • Tray popup(s) with steppers, automatic toggle, settings, quit.
  • Settings window: schedule pickers, day/night range, startup, displays.
  • Start at login (opt-in) and a full CLI mirroring every setting.
  • Scroll-on-icon adjustment with transient value bubbles (OSD).

Platform

  • Debian/Ubuntu (.deb), Arch (AUR), Fedora/openSUSE (rpm/COPR) from one codebase.
  • GNOME (Wayland), KDE, and X11 desktops; tray-less operation where no host exists.
  • Single self-contained binary; runs from the build dir with zero install.
  • The app itself never needs sudo; hardware access comes from udev rules + group membership.
  • XDG directories for config, state/log, runtime socket; freedesktop autostart entry.

2. Architecture

Cargo workspace: nmc-core (pure logic: settings, state machine, schedule math, kelvin, traits — no hardware) + nightmodecontroller-linux (backends, tray, UI, IPC, CLI). The macOS model layer was ported into the core first; Linux backends implement its traits.

Two tray channels (brightness half-disc mark, colour moon) each own a D-Bus connection and menu. One Unix-socket IPC server enforces single-instance and forwards CLI commands; a settings window (egui) mirrors all state.

3. Key decisions (with rationale)

Stack: Rust + egui + raw zbus (not Tauri, not Python)

Tauri would pull WebKitGTK (~100 MB, per-distro webview quirks) for a tray daemon; Python would need a runtime + packaging story per distro. Rust gives one ~17 MB binary with two shared-lib deps (libc6, libgcc-s1 — GUI libs are dlopen'd at runtime) and fearless refactors under 144 tests.

Tray via raw StatusNotifierItem + dbusmenu (no ayatana libraries)

Zero system-library deps and full control of the wire shapes. Hard-won rules: one item per D-Bus connection; probe theme dirs and serve an empty IconName when the packaged icon is absent (any non-empty name bypasses the embedded pixmap silently); GetLayout must declare exactly (u(ia{sv}av)) — strict hosts reject bare variants with a journal-only error while lenient clients hide the bug.

Popup UX: steppers + scroll + OSD (no sliders on GNOME)

Verified in the ubuntu-appindicators source: the Shell closes the popup on every item click with no stay-open flag, and the renderer has zero slider support. So: ± steppers for discoverability, wheel-on-icon (Scroll) for repeated adjustment, and a notification bubble showing the new value as the confirmation the popup cannot give.

Night Light schedule ownership (GNOME)

Writing Temperature while Night Light is inactive is a silent no-op, and an enabled GNOME schedule would clobber our value. On first drive the backend snapshots five keys, enforces enabled + manual + full-day window (0, 24), mirrors each target, and restores everything on reset. Probe fails closed without a readable snapshot; one-shot --status never writes keys. A reboot/SIGKILL can strand ownership (see §4).

Capability = backend AND live displays; setters persist regardless

Every hardware apply is gated on an enumerated display list, so an unplugged monitor disables driving everywhere instead of fighting Night Light for no screen. Setters still persist intent, so values survive hotplug; a slow tick re-probes displays and DDC.

Bind-first IPC; forward when live, drive directly when headless

Second invocations forward JSON commands over $XDG_RUNTIME_DIR/nightmodecontroller-linux.sock. Never unlink before bind (a racing primary can steal a live socket) and never remove on shutdown. With no daemon, setter flags drive backends directly — handy for scripts and keyboard shortcuts.

Quit on a dedicated thread, then exit(0)

eframe has no programmatic exit and minimized windows starve update(), so IPC/tray/Ctrl-C quit paths run cleanup (hardware restore, Night Light key restore) on their own thread instead of waiting on the event loop. ~10 s stop time is joins + restore, by design.

Logging: XDG state dir, stderr-only capture, rotation

The daemon dup2's stderr only into ~/.local/state/nightmodecontroller-linux/*.log (2 MB rotation, version/timestamp/pid banner). Stdout stays on the terminal and one-shot CLI never touches the log.

Theme: always follow the OS (winit + gsettings fallback)

No manual Light/Dark switch. winit reports None on XWayland, so a polled gsettings fallback (color-scheme, 5 s cadence) covers that stack; first report is logged for audit.

Docs that can't drift: CLI catalog card + strict test

The settings window lists all 18 CLI flags (selectable + copy-all). A test asserts set-equality against the clap definition, so new flags fail CI until documented. Same philosophy for the man page and --help texts.

Packaging: explicit per-family files, manual dpkg-deb

build-deb.sh stages + dpkg-deb -b (no cargo-deb dependency, version from Cargo.toml); Arch PKGBUILD + .SRCINFO + install hooks; RPM spec for COPR. All three install the same file set (binary, desktop, metainfo, two SVG icons, udev rule, gzipped man) and run the same post-install logic (create i2c group, reload udev, refresh caches, print the group-join notice).

Naming: repo nightModeController_Linux, binary/packages lowercase

Linux packaging policy forbids uppercase in .deb/.rpm/AUR names, so the binary, packages, files, and runtime paths use nightmodecontroller-linux while the repo keeps its mixed-case name. Human display strings ("Night Mode Controller") are unchanged.

4. Limitations & known gaps

  • KDE paths written but never run live (KWin backend, native SNI, KDE notifications). Kubuntu is the next required test.
  • First COPR build pending: the spec is executed-and-proven locally but not yet built on Fedora infrastructure; no Koji (offline) support.
  • Reboot/SIGKILL strands Night Light ownership (keys stay at the forced full-day window). Planned: persist the snapshot at enforce time and reconcile the (0,24) fingerprint at startup.
  • Manual mode + hotplug: reappearing monitors re-apply brightness but colour waits for the next interaction.
  • i2c group join is always manual (per-user, packages can't do it); surfaced in installer output, man page, and README.
  • No Flatpak / immutable-distro story (Silverblue); i2c access through a sandbox is uncharted. No official Fedora (Koji) build (needs vendoring).
  • Theme flips apply within ~5 s on XWayland (poll cadence), instantly where winit reports.
  • packaging/gnome-shell-extension/ is a frozen experiment, never installed or shipped; the SNI path needs no extension on KDE and rides Ubuntu's preinstalled AppIndicator support on GNOME.
  • Runtime paths renamed in the 1.0.0 rebrand (socket, log, config, autostart entry): pre-release installs start from default settings.

5. Dependencies

Runtime (shipped .deb)

  • libc6, libgcc-s1 — the only linked libs (verified via ldd).
  • X11/Wayland/GL client libs — dlopen'd at runtime, present on any GUI system.
  • Recommends: i2c-tools (DDC debugging). Suggests: AppIndicator shell extension (Debian GNOME).

Build

  • cargo, rustc, a C linker (gcc, or zig-cc shim where no toolchain exists).
  • Key crates: tokio, zbus, egui/eframe 0.33, clap 4, serde, dirs, rustix, chrono. Cargo.lock is committed for reproducible releases.

Packaging tools

  • .deb: dpkg-deb only. Arch: makepkg. RPM: COPR (buildscm from the release tag).

6. Setup & install

Install (per distro)

Releases live at github.com/prompt-smithy/nightModeController_Linux/releases; each release attaches the .deb (nightmodecontroller-linux_<version>_amd64.deb).

Ubuntu, Kubuntu, Mint, Pop!_OS, Zorin (.deb) 
sudo apt install ./nightmodecontroller-linux_1.0.0_amd64.deb

Use apt install ./file.deb, not bare dpkg -i, so dependencies resolve. GUI alternative: double-click the file (Software / Discover) and install graphically. On Kubuntu the tray icon appears immediately — Plasma has a native StatusNotifier host, no extension needed. On Ubuntu GNOME the icon rides the preinstalled AppIndicator support.

Debian (.deb) 
sudo apt install ./nightmodecontroller-linux_1.0.0_amd64.deb

Same file as Ubuntu. On vanilla Debian GNOME, install an AppIndicator shell extension (a package Suggests) or the tray icon has no host — the app still runs via its settings window and CLI.

Arch, Manjaro, EndeavourOS (AUR) 
yay -S nightmodecontroller-linux
# or without an AUR helper:
#   git clone the AUR repo, then makepkg -si

The AUR package builds from the release tag tarball. DDC/CI needs the i2c-dev module: sudo modprobe i2c-dev (persist via /etc/modules-load.d/i2c-dev.conf if wanted), then the group join below like every other distro.

Fedora, RHEL, CentOS (COPR .rpm) 
sudo dnf copr enable <you>/nightmodecontroller-linux
sudo dnf install nightmodecontroller-linux

Replace <you> with the maintainer's COPR name (see packaging/rpm/COPR.md). First COPR build is still pending — until it exists, build from source below.

openSUSE and everything else (build from source)

No published binary yet. The release binary links only libc, so building on the machine itself always works:

cargo build --release -p nightmodecontroller-linux
sudo install -Dm755 target/release/nightmodecontroller-linux \
    /usr/local/bin/nightmodecontroller-linux

Then install the udev rule by hand and do the group join below: sudo install -Dm644 packaging/51-nightmodecontroller-linux-i2c.rules /usr/lib/udev/rules.d/ && sudo udevadm control --reload.

DDC/CI access (all distros, still required after install)

sudo modprobe i2c-dev            # load the I2C bus driver
sudo usermod -aG i2c "$USER"     # grant this user raw bus access
# log out and back in, then:
nightmodecontroller-linux --status

What each step does: modprobe creates the /dev/i2c-* nodes; the installer drops a udev rule assigning those nodes to group i2c (creating the group if missing); the usermod line puts you in that group — the one step a package can never do. /dev/i2c-* ships root-only, so without it every bus open fails with permission denied.

Build from source

cargo build --release -p nightmodecontroller-linux
./target/release/nightmodecontroller-linux        # tray app
./target/release/nightmodecontroller-linux --status

First launch checklist

  • Both tray icons appear; popups open; scroll shows value bubbles.
  • Settings window opens (Startup/Displays/Command-line start collapsed).
  • Automatic schedule visibly warms the screen at night; brightness moves the monitor.
  • Quit restores the user's Night Light keys; log lands in the state dir (§3).

7. Verification matrix

  • 144 tests (cargo test --workspace) + clippy-clean + fmt-checked. Live-hardware tests are #[ignore]d by default and run manually (Night Light round-trip, OSD path).
  • Proven-fail regression tests: tray drive() bridge, CLI catalog drift, OSD urgency pin, pixmap shape witnesses.
  • Distro order after Ubuntu: Kubuntu → Debian stable → Arch → Fedora (new DE, oldest stack, rolling ceiling, rpm/SELinux). DDC needs bare metal per GPU vendor; everything else validates in VMs.
  • Installer proof (v1.0.0): .deb rebuilt + extracted binary runs --status; full rpmbuild -ba in a user-local rpm toolchain + extracted binary runs; PKGBUILD package() simulated file-for-file (real makepkg needs Arch).
